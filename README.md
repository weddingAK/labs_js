# Lab 01: Event Loop, Game Loop & Physics

## Опис проекту

У рамках цієї лабораторної було створено ігровий цикл з фіксованим кроком (Fixed Timestep / accumulator) на базі `requestAnimationFrame`, ізольований модуль керування через замикання (closure), чисту фізику корабля та рендеринг через Canvas 2D API з підтримкою `devicePixelRatio`.

---

## Експерименти ("Зламай навмисно і поміряй")

### 1. Блокуючий цикл у кадрі (Blocking loop in frame)

- **Що зроблено:** Всередині функції `update` або `render` було додано штучну важку синхронну операцію (наприклад, цикл `while` на 100+ мс).
- **Результати / Числа:** FPS різко падає з 60 до ~5-8 кадрів на секунду. Інтерфейс (HUD) та клавіатура починають сильно «фризити» та затримуватись.
- **Пояснення через Event Loop:** JavaScript виконується в одному потоці (Call Stack). Синхронна важка операція повністю забиває стек викликів. Оскільки браузер не може виконувати рендеринг або обробку подій (Task Queue / Microtask Queue / rAF), поки стек зайнятий, екран «заморожується», а кадри пропускаються.

### 2. Використання `setInterval` замість `requestAnimationFrame`

- **Що зроблено:** Ігровий цикл було переведено з `requestAnimationFrame(loop)` на `setInterval(loop, 1000 / 60)`.
- **Результати / Числа:** На моніторах з частотою 144 Гц рух став ривкоподібним (stuttering). Події таймера не синхронізовані з оновленням екрана дисплея (VSync), що призводить до мікропауз або дублювання кадрів.
- **Пояснення через Event Loop:** `setInterval` розміщує callback-функції у чергу задач (Task Queue / Macrotasks) незалежно від циклу рендерингу монітора. Натомість `requestAnimationFrame` синхронізований безпосередньо з частотою оновлення дисплея і спрацьовує одразу перед наступним перемальовуванням екрана (repaint).

### 3. Змінний крок (Variable Timestep / без акумулятора)

- **Що зроблено:** Фіксований крок симуляції було замінено на змінний (`dt`, що передається напряму з `requestAnimationFrame`).
- **Результати / Числа:** Швидкість руху корабля та фізики стала залежати від поточного FPS. При зниженні FPS (наприклад, якщо навантажити процесор) гра починає уповільнюватися («slow motion»), а при нестабільному FPS фізика стає не детермінованою (користувач може проходити крізь стіни або перелітати далі).
- **Пояснення через Event Loop:** Змінний `dt` робить симуляцію залежною від часу виконання конкретного кадру. Якщо у браузері стається просадка кадрів, велике значення `dt` викликає величезний стрибок координат об'єкта, порушуючи закони інтегрування фізики.
