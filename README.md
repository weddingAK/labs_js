# Lab 03: Asynchronous JavaScript, Promises, async/await & Loading Pipeline

## Опис проекту

У третій лабораторній роботі реалізовано асинхронний конвеєр завантаження ігрових ассетів (спрайтів та аудіо) за допомогою `Promise.all` та `fetch` із механізмом повторних спроб (_exponential backoff + jitter_) і захистом через `AbortSignal`. Додано підтримку Web Audio API, шину подій на базі `EventTarget` (`EventBus`), а також асинхронне лобі вибору кімнат перед стартом гри.

---

## 1. Порівняння Sequential `await` vs Concurrent (`Promise.all`)

- **Sequential (`for...of` з `await` всередині):** Завантаження кожного файлу чекає завершення попереднього. Загальний час дорівнює сумі часу завантаження всіх ассетів ($T_1 + T_2 + ... + T_n$). Це призводить до довгастого завантаження і менш ефективного використання мережі.
- **Concurrent (`Promise.all`):** Усі запити на завантаження запускаються паралельно. Загальний час завантаження дорівнює часу найповільнішого файлу ($\max(T_1, T_2, ..., T_n)$). Це забезпечує максимальну швидкість старту гри та дозволяє коректно вираховувати загальний прогрес для прогрес-бару.

## 2. Головоломки порядку (Microtasks / Tasks / rAF)

Головоломка 1: `await` та мікрозадачі

```javascript
console.log('1');
async function test() {
  console.log('2');
  await Promise.resolve();
  console.log('3');
}
test();
console.log('4');
Вивід: 1, 2, 4, 3
Пояснення: Код до першого await виконується синхронно (1, 2). Зустрівши await, виконання функції ставиться на паузу, створюється мікрозадача, а керування повертається у зовнішній код (4). Після завершення синхронного стека виконуються мікрозадачки (3).

Головоломка 2: setTimeout всередині .then
JavaScript
Promise.resolve().then(() => {
  console.log('A');
  setTimeout(() => console.log('B'), 0);
});
console.log('C');
Вивід: C, A, B
Пояснення: Синхронний C виводиться першим. Потім виконується мікрозадача (A), яка ставить макрозадачу setTimeout у Task Queue. Після очищення мікрозадач цикл подій бере макрозадачу і виводить B.


Головоломка 3: Порядок requestAnimationFrame та Microtasks

JavaScript
requestAnimationFrame(() => console.log('rAF'));
Promise.resolve().then(() => console.log('Promise'));
console.log('Sync');
Вивід: Sync, Promise, rAF
Пояснення: Синхронний лог йде першим (Sync). Мікрозадачки (Promise) виконуються одразу після порожнення стека викликів, до перемальовування сторінки. Колбек requestAnimationFrame виконується браузером перед наступним рендерингом кадру.


Головоломка 4: Вкладені await

JavaScript
async function f() {
  await 1;
  await 2;
  console.log('done');
}
f();
console.log('after');
Вивід: after, done
Пояснення: Кожен await розгортається у ланцюжок мікрозадач. Спочатку відпрацьовує синхронний код після виклику функції (after), а потім послідовно резолвляться проміси (done).


Головоломка 5: Змішування setTimeout і Promise

JavaScript
setTimeout(() => console.log('timeout'), 0);
Promise.resolve().then(() => console.log('promise'));
console.log('start');
Вивід: start, promise, timeout
Пояснення: Макрозадача setTimeout потрапляє в Task Queue, тоді як Promise.then створює мікрозадачу в Microtask Queue. Мікрозадачі мають вищий пріоритет і виконуються одразу після поточного макрокроку (синхронного коду).


3. Галерея збоїв (Robustness)
404 спрайта: Механізм retryWithBackoff перевіряє статус відповіді (response.status), і якщо це клієнтська помилка 4xx (наприклад, 404 Not Found), ретраї не виконуються і одразу генерується зрозуміла помилка, перериваючи завантаження без зациклювання.
Таймаут мережі / Повільне з'єднання: Використання AbortSignal.timeout() у запитах лобі запобігає зависанню клієнта при відсутності зв'язку з сервером.
Abort посеред завантаження: Якщо гравець закриває вкладку або перериває процес, AbortController скасовує всі активні HTTP-запити та зупиняє декодування зображень.
Битий JSON: Помилки парсингу відловлюються блоком try...catch, а екран завантаження виводить повідомлення про помилку замість падіння всього додатку.
```
